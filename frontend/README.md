# frontend

Интерфейс Sapa: три экрана, «Диалоги», «Разбор диалога» и «Оценочный лист», плюс подробный отчёт из меню. Спецификация в [design/SAPA_UI_SPEC.md](../design/SAPA_UI_SPEC.md), контракт в [CONTRACTS.md](../CONTRACTS.md), типы в `src/api/types.ts` повторяют `ai/src/cqa_ai/contracts.py`.

Стек: Vite, React, TypeScript, Tailwind. Нужен Node 24.

## Запуск

```bash
cd frontend
npm install
```

Без backend, на синтетических данных:

```bash
npm run dev:mock
```

С backend на `http://localhost:8000`:

```bash
npm run dev
```

Браузер ходит на `/api`, Vite проксирует запросы на backend. Другой адрес задаётся так: `BACKEND_URL=http://localhost:9000 npm run dev`.

Откройте адрес, который напечатает Vite.

## Сборка и проверка

```bash
npm run typecheck    # проверка типов
npm run build        # рабочая сборка в dist/, без слоя моков
npm run build:mock   # статическая сборка с моками
npm run preview      # раздача dist/
```

Сборка статическая: относительные ассеты (`base: './'`) и `HashRouter`, поэтому её можно положить как HTML-компонент Dynamics 365.

## Настройка

| Что | Где |
|---|---|
| Адрес API | `apiBaseUrl` в `dist/config.js` меняется без пересборки. Запасной вариант `VITE_API_BASE_URL`, по умолчанию `/api` |
| Моки | `VITE_USE_MOCKS=true` при сборке или запуске |
| Хост | `src/host/hostAdapter.ts`. Компонент Dynamics может задать `window.__CQA_HOST__` до загрузки бандла |

Всё с префиксом `VITE_` и `config.js` попадают в браузер. URL организаторов, `audio_url` и ключи туда класть нельзя.

Если сборка раздаётся не через прокси, backend должен разрешить CORS для её адреса.

## Моки

Слой `src/mocks/` хранит состояние в памяти, перезагрузка страницы его сбрасывает. Диалоги выдуманы, реальных данных нет. В рабочую сборку слой не попадает.

| Диалог | Что показывает |
|---|---|
| `A-1042` | Диалог из макета: открытая апелляция на «Завершение», итог 77,69 |
| `A-1034` | Не применимо с перераспределением веса |
| `A-1040` | Грубое нарушение при высоком итоге, повторяющиеся метки времени |
| `A-1041` | Пропущенное действие: проверенный участок и ожидаемое место |
| `A-1039` | Спорные места и апелляция на шкальный критерий |
| `A-1033` | Результат на синтетических данных |
| `A-1036` | Частичный итог |
| `A-1037` | Сбой, повторная оценка тоже падает |
| `A-1030` | Звонок не отправлен в модель, удержание в расшифровке |
| `A-1038` | Условный звонок с кнопкой записи |
| `A-1035` | Диалог без оценки |
| `A-1032` | Канал без оценочного листа: оценка по каналу даёт сбой |

Импорт по любому `group_id` добавляет ещё два диалога и показывает предупреждение. Новая оценка в моках идёт по этапам за несколько секунд и сохраняет прежние ответы, если они подходят к версии листа.

## Маршрут для проверки

1. «Диалоги»: перетащить файл `.json` на страницу, новая строка покажет этапы и итог.
2. Открыть `A-1042`, раскрыть «Завершение»: объяснение, кольцо на реплике, линия к ней.
3. «Изменить на «Да»», причина и проверяющий: итог переедет на 85,38, рядом останется исходная 77,69.
4. «Оценочный лист»: выключить уточнение или изменить вес, сохранить версию 2.
5. В разборе «Оценить заново» с версией 2, затем «История оценок».

## Проверка с backend

```bash
cd backend
CQA_DB_PATH=/tmp/cqa-check.sqlite CQA_ALLOW_MOCK=1 uv run uvicorn cqa_backend.main:app --port 8000
```

Затем `npm run dev` в `frontend/`. Без `CQA_ALLOW_MOCK` и провайдера оценка завершается сбоем с текстом в поле `error`, так удобно смотреть экран сбойного запуска.
