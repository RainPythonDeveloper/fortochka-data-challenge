# backend

HTTP API, импорт, SQLite, jobs, версии чек-листов, апелляции и экспорт. Контракт в [CONTRACTS.md](../CONTRACTS.md).

## Запуск

```bash
cd backend
uv sync
uv run pytest
uv run uvicorn cqa_backend.main:app --port 8000
```

Настройки читаются из `.env` в корне репозитория, переменные окружения важнее файла. Запускайте один процесс: очередь оценок живёт внутри него.

Проверка на заглушке:

```bash
CQA_ALLOW_MOCK=1 uv run uvicorn cqa_backend.main:app --port 8000
curl -X POST localhost:8000/imports -H 'content-type: application/json' -d '{"group_id":"DEV"}'
```

Документация маршрутов: `http://localhost:8000/docs`.

## Переменные окружения

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `CQA_API_URL` | нет | URL API организаторов без `group_id`, в одинарных кавычках. Содержит подпись |
| `CQA_GROUP_ID` | нет | Группа, если в `POST /imports` она не передана |
| `CQA_DB_PATH` | `backend/cqa.sqlite` | Путь к базе |
| `CQA_CORS_ORIGINS` | `http://localhost:5173,http://127.0.0.1:5173` | Разрешённые источники через запятую |
| `CQA_HTTP_TIMEOUT_S` | `30` | Таймаут запроса к API организаторов |
| `CQA_EVAL_CONCURRENCY` | `3` | Сколько диалогов оценивается одновременно |
| `CQA_EVAL_PAUSE_S` | `3` | Пауза между началами оценок, секунды. Попадания в кэш паузу не занимают, `0` выключает |
| `CQA_EVAL_TIMEOUT_S` | `300` | Предел на оценку одного диалога |
| `CQA_ALLOW_MOCK` | выключено | `1` разрешает заглушку `mock` |
| `LLM_PROVIDER`, `LLM_MODEL` | нет | Провайдер и модель оценщика: `nvidia` и `google/gemma-4-31b-it` |
| `LLM_FALLBACK_MODEL` | нет | Запасная модель, входит в ключ кэша |
| `LLM_PIPELINE` | `single` | Схема оценки, входит в ключ кэша |
| `NVIDIA_API_KEY` | нет | Ключ провайдера, его читает `cqa_ai`. Маскируется в логах и ошибках |
| `CQA_ALLOW_VOICE_TO_CLOUD` | `1` | Звонки оценивает настроенная модель. `0`: только локальная модель, иначе `failed` с причиной `personal_data_not_sent` |

Заглушка работает только при `CQA_ALLOW_MOCK=1`, даже если указано `LLM_PROVIDER=mock`. Если провайдер задан, заглушка не подставляется: при сбое диалог получает статус `failed`.

## Контрольный прогон

```bash
uv run python -m cqa_backend.control --group-id <значение>
```

Импорт, проверка числа записей, схемы и уникальности, оценка, повтор только неполных диалогов, проверка полноты, экспорт JSON и CSV, отчёт в консоль. Импорт использует ту же базу, что и сервер, поэтому результаты сразу видны в интерфейсе.

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `--expected-records` | `10` | Сколько записей должно прийти. Иначе прогон останавливается до записи в базу |
| `--checklist-id` | нет | Один чек-лист для всех диалогов. Без него выбор по каналу |
| `--checklist-for` | нет | Чек-лист для канала, можно повторять: `--checklist-for "voice call=<id>"`. Нельзя вместе с `--checklist-id` |
| `--max-retries` | `2` | Сколько раз повторять неполные диалоги |
| `--retry-delay` | `30` | Пауза перед повтором, секунды |
| `--out-dir` | `data/control/<группа>-<время>` | Папка экспорта. Папка, которую Git отслеживал бы, отклоняется |
| `--force` | выключено | Первый раунд не берёт результаты из кэша |
| `--allow-mock` | выключено | Разрешает заглушку. Одного `CQA_ALLOW_MOCK=1` мало |

Коды выхода: `0` всё полно, `1` есть сбойные или неполные диалоги, `2` прогон остановлен до оценки.

## Поведение, которое контракт не уточняет

- `Job.done` считает успешные диалоги, `Job.failed` сбойные. Задача завершена со статусом `failed`, только если не удался ни один диалог.
- Сбойный диалог остаётся запуском со статусом `failed`, пустыми `results` и итогом `null`. Текст ошибки лежит в поле `error`.
- Если `evaluate` вернул `failed` по всем критериям, запуск тоже `failed`: `error` берётся из первого `justification`, попытки и стоимость остаются в журнале. Если сбойные только часть критериев, запуск `done` с частичным итогом. Такие запуски не используются как кэш.
- После рестарта незавершённые задачи продолжаются с необработанных диалогов.
- Предупреждения импорта лежат в `ImportResult.errors` с префиксом `warning:`. `POST /transcripts` возвращает их в дополнительном поле `warnings`.
- Повторный импорт обновляет запись и `audio_url`. Прошлые запуски хранят свой снимок.
- `latest_total`, `gross_error` у диалога и `gross_error` у запуска показывают текущее состояние после решений. Экспорт отдаёт только исходные значения.
- Экспорт берёт последний запуск каждого диалога. Диалоги без запуска идут со статусом `not_evaluated`. Необязательный параметр `checklist_id` сужает выборку до одного чек-листа.
- Запуск по чек-листу чужого канала не блокируется, но получает причину проверки `channel_not_in_checklist`.
- В `evaluate` снимок передаётся без `audio_url`.
- Без `checklist_id` в `POST /evaluations` чек-лист выбирается для каждого диалога по каналу из последних версий. Если канал заявлен в нескольких чек-листах, берётся стандартный из `load_default_checklists()`, всегда его последняя версия. Если стандартного нет, а подходящих несколько, ответ 422. Если подходящего нет совсем, диалог получает `failed` с `checklist: null`, остальные продолжаются.
- `checklists_by_channel` назначает чек-лист каналу явно, берётся его последняя версия. Каналы вне этого поля выбираются автоматически. Вместе с `checklist_id` это 422, неизвестный чек-лист даёт 404.
- `GET /reports/summary` считает диалоги по последнему запуску, а задержку и стоимость по всем запускам с вызовом модели. Попадания в кэш и неотправленные звонки в них не входят. У бесплатного API стоимость равна 0. Запуски с вызовом, но без данных о стоимости показаны в `runs_without_cost`.
- `GET /evaluations/compare` сравнивает исходные результаты. Итоги после решений показаны отдельно в `final_total_delta`.
