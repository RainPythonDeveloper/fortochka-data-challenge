# Sapa: спецификация интерфейса для реализации

Этот файл для агента, который будет переделывать интерфейс в `frontend/`. Задача: собрать три экрана ровно так, как они выглядят и двигаются в утверждённом макете. Здесь всё, что нужно: что строить, из каких данных, как это выглядит, как двигается, какие слова на экране и что считается готовым.

Перед работой прочитайте:

1. [AGENTS.md](../AGENTS.md), разделы 0, 5, 6, 7 и 19. Там правила, которые нельзя нарушать, обязательные функции и расчёт баллов.
2. [CONTRACTS.md](../CONTRACTS.md): HTTP API и форма данных.
3. Этот файл целиком.

## 2. Ветки и порядок работы

- Работайте в `feat/frontend`. Перед началом влейте свежий `main`: в нём этот файл и макет.
- Меняйте только `frontend/`. Что нужно от `backend/` и `ai/`, описано в разделе 8. Это отдельные задачи для их владельцев, сами не правьте.
- Пока бэкенд не добавил новые поля, интерфейс работает на текущем API. Все новые поля необязательные, у каждого есть запасное поведение (раздел 8).
- Мок-слой `src/mocks/` обновите под новые экраны. Только синтетические данные, никаких реальных звонков.
- Коммитить только по просьбе человека. Проверка на секреты перед пушем: команда в README.

## 3. Визуальная система

### 3.1 Принцип

Плоский светлый интерфейс в духе Freedom:

- тёмно-зелёная шапка;
- светло-серый фон;
- белые панели со скруглением 14 без теней и рамок.

Один уровень контейнеров: панель внутри панели запрещена. Структуру задают отступы и тонкие линии между строками. Цвет работает только как смысл: зелёный для хорошего ответа, связи и главного действия, красный только для «Нет» и грубых нарушений, жёлтый для «изменён», «спорно» и «сбой». Всё остальное в оттенках серого.

### 3.4 Сетка и размеры

- Целевой экран 1440×900, минимум 1280×800. Страница не прокручивается: прокручиваются панели внутри. Ниже 1024 по ширине панели встают в столбец, и прокручивается страница.
- Шапка высотой 52 на всю ширину.
- Под шапкой фон `--color-ground`, внутренний отступ 16, промежутки между панелями 12.
- Панель: скругление 14, отступы 20–24 одинаковые со всех сторон, без тени и рамки.
- Строки списков: высота 44–52, отступ по бокам 12. Подсветка при наведении на всю строку с внутренним скруглением 10 (отрицательный отступ −12 у строки, внутренний +12, как в макете).
- Бейджи: скругление 999, отступы 3×10.
- Кнопки: скругление 10. Большая 40 в высоту, обычная 32.
- Иконки: установите `lucide-react`. Один размер 16, толщина 1.75, один цвет. Эмодзи и самодельных значков нет.

### 3.6 Бейдж ответа

| Состояние критерия | Текст | Цвета |
|---|---|---|
| Да/Нет, ответ «yes» | Да | `--color-green-soft` / `--color-green-deep` |
| Да/Нет, ответ «no» | Нет | `--color-red-soft` / `--color-red-text` |
| Шкала | «15 из 20» (значение из максимума `levels`) | `--color-chip` / `--color-ink` |
| `not_applicable` | Не применимо | `--color-chip` / `--color-text` |
| Флаг грубого нарушения (`criterion.flag`), ответ «no» | Не выявлены | `--color-green-soft` / `--color-green-deep` |
| Флаг, ответ «yes» | Выявлено | `--color-red-soft` / `--color-red-text` |
| `unassessable` | Нельзя оценить | `--color-amber-soft` / `--color-amber-text` |
| `failed` | Сбой | `--color-amber-soft` / `--color-amber-text`, причина в объяснении |

Для флага действует обратная полярность: «Да» значит нарушение (AGENTS.md, раздел 7).

## 4. Экран «Диалоги» (`/conversations`)

Эталон: `stills/sapa-dialogs-poster.png` и `sapa-dialogs-beats.png`.

### 4.1 Композиция

Сверху вниз:

1. **Панель-шапка, одна строка:**
   - слева заголовок «Диалоги»;
   - через 40 три цифры: «**58** из 65 оценено», «**81,4** средний итог», «**7** грубых нарушений», последняя цифра красным;
   - справа кнопка primary «Загрузить диалог» и кнопка-иконка «⋯» (`aria-label="Ещё"`) с меню: «Импорт по group_id», «Экспорт JSON», «Экспорт CSV», «Подробный отчёт».
2. **Над таблицей вкладки текстом:**
   - «Все 65», «Требуют внимания 9», «Апелляции 2»;
   - активная 600 с зелёной чертой 2px снизу;
   - справа поле поиска по номеру диалога.
3. **Панель-список, таблица.** Колонки: «Диалог» 150, «Канал» 140, «Итог» 90 (по правому краю), «Отметка» 300, «Когда» по правому краю.
   - Строка 52 высотой.
   - Номер 14/600, теги «Чат»/«Звонок» и язык, итог 15/700.
   - Отметка: одна короткая фраза или пусто.
   - Время относительное: «5 мин», «только что».
   - Строка целиком ведёт в разбор.

### 4.2 Откуда цифры

| Что | Источник |
|---|---|
| Оценено X из Y | `GET /reports/summary`: `evaluated` из `conversations` |
| Средний итог | Среднее `latest_total` по `GET /conversations` (без null), одна цифра после запятой |
| Грубых нарушений | Число диалогов с `gross_error = true` |
| Строки таблицы | `GET /conversations`, сортировка по времени последней оценки, новые сверху |
| Отметка | Приоритет: грубое нарушение («Грубое нарушение», красным 600) → открытая апелляция («Апелляция ждёт решения») → сбой («Сбой: …» жёлтым, или «Не отправлен: персональные данные» для звонков с причиной `personal_data_not_sent`) → спорные места при `review_status = flagged` («Есть спорные места», серым) → не оценён («Не оценён» и текстовая кнопка «Оценить») → пусто |
| Вкладка «Требуют внимания» | Грубое нарушение, сбой, не оценён или спорные места |
| Вкладка «Апелляции» | Диалоги с апелляциями `status = open` (`GET /appeals?status=open`, по `evaluation_id`) |

Пока бэкенд не отдаёт статус последнего запуска и число открытых апелляций в `ConversationSummary` (раздел 8.3), берите их отдельными запросами `GET /evaluations?conversation_id=` и `GET /appeals?status=open`. Делайте это лениво, только для видимых строк.

### 4.3 Загрузка перетаскиванием

- Файл можно бросить в любое место страницы. Пока файл над страницей, панель-список подсвечивается:
  - рамка 2px `--color-green` внутри панели;
  - фон `#F7FCF9`;
  - переход 150 мс.
- Кнопка «Загрузить диалог» открывает выбор файла: `.json` в формате API организаторов, можно несколько файлов.
- **«Импорт по group_id»** в меню открывает маленькую форму прямо под шапкой (не модальное окно): поле и кнопка «Импортировать». После импорта появляется строка-уведомление «Импортировано 65, пропущено 0» и кнопка «Оценить неоценённые».
- **Загрузка ссылкой** идёт тем же полем, если бэкенд добавит приём ссылки. Пока его нет, этой опции не показывайте.
- Предупреждения импорта (`warning:` в `errors`) показывайте под уведомлением серым списком.

### 4.4 Новая строка и оценка в ней

После загрузки файла (`POST /transcripts`) сразу запускайте оценку (`POST /evaluations` с этим `conversation_id`, чек-лист по каналу). Строка появляется сверху:

- **Появление:** высота раскрывается от 0, строка приходит целиком, сдвигая остальные вниз, 250 мс, `cubic-bezier(0.16, 1, 0.3, 1)`.
- **Пока идёт оценка:**
  - фон строки `#EEF9F2`;
  - в колонке «Итог» полоса прогресса шириной 84;
  - в «Отметке» спиннер 14 и название текущего этапа;
  - в «Когда» «только что».
- **Этапы в строке:** «Разбор диалога» → «Оценка моделью» → «Проверка цитат». Смена названия идёт перекрёстным затуханием 200 мс, текст не прыгает: ячейка держит ширину самого длинного варианта.
- **Полоса прогресса честная.** Если бэкенд отдаёт текущий этап (раздел 8.2), полоса стоит на 10% на разборе, на 85% во время оценки моделью и на 95% на проверке. Если не отдаёт, вместо полосы показывайте прошедшее время «0:42»: процентов модель не сообщает, и выдумывать их нельзя.
- **Счётчик «3 из 8 критериев»** в макете иллюстративен. Модель отдаёт все критерии сразу, поэтому в приложении его нет, пока бэкенд не начнёт отдавать частичные результаты.
- **Готово:**
  - итог прокручивается к значению (раздел 6);
  - в «Отметке» «Оценено за 1 мин 5 с» зелёным, время из `log.latency_ms`;
  - подсветка строки гаснет за 1,2 с с задержкой 0,6 с.
- **Сбой:** в «Отметке» «Сбой: <короткая причина>» жёлтым и текстовая кнопка «Повторить». Ноль не показывать никогда.

## 5. Экран «Разбор диалога» (`/conversations/:id`)

Эталон: `stills/sapa-review-poster.png` и сюжет в `stageshow/REHEARSAL.md`.

### 5.1 Композиция

Две зоны под шапкой:

1. **Панель-шапка разбора** на всю ширину, отступ 22×24. Слева столбец, справа блок итога шириной 210.

   Строка заголовка:
   - «Диалог A-1042» (номер из `conversation_id`);
   - теги канала и языка: «Чат» или «Звонок», «Русский», «Казахский», «Английский»;
   - при `final_score.gross_error` красная таблетка «Грубое нарушение» (фон `--color-red-soft`, текст `--color-red-text`, 12/600);
   - для звонков с записью кнопка-текст «Открыть запись»;
   - справа в строке текстовые кнопки «Оценить заново» и «История оценок» (вторая, только если запусков больше одного; открывает сравнение запусков).

   Под заголовком через 16 лента этапов (5.2).

   Справа итог (5.3).
2. **Две панели в ряд:** «Переписка» шириной 400 и «Оценка по критериям» на остаток. Обе на всю оставшуюся высоту экрана, каждая прокручивается сама.

Строки «Чат · RU · Чек-лист чатов, версия 1» больше нет. Канал и язык показаны тегами. Версия оценочного листа видна в «Истории оценок» и во всплывающей подсказке на ленте этапов.

### 5.2 Лента этапов

- Четыре колонки равной ширины: «Разбор диалога», «Оценка моделью», «Проверка цитат», «Расчёт итога».
- В каждой колонке отметка 14×14, название 13/500 и под ним время 12 серым.
- Между отметками линия 2px (`#E3E7EC`); когда этап готов, она становится `#B9E5C8`.
- **Отметка по состоянию:**

Обязательные функции 05 и 06. Авторизации нет: подача и решение — два разных действия в одном интерфейсе.

| Состояние | Что показано |
|---|---|
| Апелляции нет | Текстовая кнопка «Оспорить оценку» |

- для Да/Нет — противоположный ответ;

### 5.7 Линия от критерия к доказательству

Подпись макета: при открытии критерия от его строки к реплике-доказательству рисуется тонкая зелёная линия.

- **Геометрия.** SVG-слой поверх области двух панелей, `pointer-events: none`. Начало: левый край строки критерия минус 4, середина по высоте. Конец: правый край пузыря реплики плюс 6, середина.

## 6. Движение

Общие правила из Impeccable и stageshow, которые мы приняли:

- Движение только там, где оно объясняет причину и следствие.
- Длительности 150–250 мс для обычных переходов, 250–450 мс для раскрытий, до 800 мс для одного авторского момента (маркер шкалы).
- Появление с замедлением в конце: `cubic-bezier(0.16, 1, 0.3, 1)`. Исчезновение быстрее появления.
- Анимируются только `transform`, `opacity`, `stroke-dashoffset` и цвет. Ширину и высоту не анимировать, кроме раскрытия высоты через grid-трюк.

| Момент | Как |
|---|---|
| Ответы критериев после получения результата | Заглушка (серая таблетка 44×22 с медленным бликом 1.5 с) заменяется бейджем в той же ячейке: бейдж проявляется с подъёмом на 3px за 300 мс, строки сверху вниз с шагом 60 мс. Это показ уже готового результата, не имитация работы модели |
| Итог | Значение досчитывается от прежнего к новому за 600 мс, `easeOutCubic`, `tabular-nums`. Из «—» в число: досчёт от 0 |
| Маркер шкалы | `left` за 800 мс, `cubic-bezier(0.16, 1, 0.3, 1)`, задержка 300 мс после итога |
| Кольцо доказательства | 250 мс |
| Номера проверенного участка | Цвет за 250 мс |
| Смена текста в одной ячейке (этап, подпись под итогом, кнопки решения) | Перекрёстное затухание 200 мс в ячейке шириной с самый длинный вариант. Ничего не прыгает |
| Новая строка в «Диалогах» | Раскрытие высоты 250 мс, подсветка гаснет за 1,2 с |
| Подсветка списка при перетаскивании | 150 мс |

Если включено «уменьшить движение» (`prefers-reduced-motion: reduce`): блики заглушек, сдвиги и досчёт выключены, значения ставятся сразу, затухания цвета остаются. Анимации на JavaScript проверяют это через `matchMedia`.

Запрещено:

- проценты прогресса, которых система не знает;
- прыгающие и пружинящие кривые;
- анимация при каждой загрузке страницы;
- блики и свечение ради украшения.

## 8. Что нужно от backend и ai

Это задачи для владельцев `backend/` и `ai/`. Порядок по CONTRACTS.md: правка контракта в `main`, затем слияние в ветки. Фронтенд работает и без них, на запасном поведении.

### 8.1 Время этапов в журнале запуска (backend)

В `EvaluationRun.log` добавить необязательное поле:

```ts
stages?: { id: 'parse' | 'model' | 'validate' | 'score'; ms: number }[]
```

Как его заполнять:

- `parse`: снимок и разметка служебных событий;
- `model`: сумма времени вызовов модели;
- `validate`: проверка ответа и цитат;
- `score`: расчёт итога.

Запасное поведение: время модели из `log.attempts`, общее время из `log.latency_ms`.

### 8.2 Текущий этап задачи (backend)

В `Job` добавить необязательное:

```ts
current?: { conversation_id: string; stage: 'parse' | 'model' | 'validate' | 'score'; started_at: string }[]
```

Это этапы диалогов, которые сейчас в работе. Запасное поведение: этап «Оценка моделью» со счётчиком прошедшего времени.

### 8.3 Статус в сводке диалога (backend)

В `ConversationSummary` добавить необязательные `latest_status: 'done' | 'failed' | null`, `latest_error: string | null`, `open_appeals: number`, `review_status: 'clear' | 'flagged' | null`, `latest_evaluated_at: string | null`. Запасное поведение: отдельные запросы (4.2).

### 8.4 Выключение уточнений (ai и контракт)

- В `Criterion` (`ai/src/cqa_ai/contracts.py`) добавить `disabled_notes: list[str] = []`.
- `effective_notes` в `ai/src/cqa_ai/rubric.py` исключает из унаследованных и своих уточнений всё, что есть в `disabled_notes`.
- `disabled_notes` входит в `checklist_hash`, потому что меняет смысл.
- Фронтенд переключателем перекладывает текст уточнения между `team_notes` и `disabled_notes`.
- Тест в `ai/tests`: выключенное уточнение по умолчанию не попадает в промпт.

### 8.5 Загрузка ссылкой (backend, по желанию)

`POST /transcripts` с `{ "url": "..." }`: сервер сам скачивает запись. Подписанные ссылки в журнал не пишутся. Пока этого нет, в интерфейсе загрузка ссылкой не показывается.

Названия критериев на экране берутся из поля `title` версии оценочного листа как есть. В макете они сокращены для иллюстрации («Ведение диалога» вместо «Управление диалогом, скорость и грамотность»). В приложении официальные формулировки не меняются (AGENTS.md, раздел 6): их можно изменить только в редакторе листа, и это будет новая версия. ## 11. Чего не делать

- Карточки внутри карточек, тени, цветные полосы сбоку блоков, градиенты на фонах.
- Иконки ради украшения, эмодзи, самодельные логотипы, буквы в цветных квадратах.
- Подписи модели повсюду. Модель называется только в подсказке этапа «Оценка моделью» и в журнале.
- Выдуманный прогресс, проценты и счётчики, которых не отдаёт API.
- Ноль вместо сбоя. Сбой всегда виден как сбой (AGENTS.md, правило 6).
- Ответы, привязанные к `conversation_id`, и любые захардкоженные результаты (правило 1).
- `audio_url`, подписанные ссылки и ключи в браузере, в `VITE_*` и в логах (правило 4).
- Реальные звонки и их цитаты в моках, скриншотах и коммитах (правило 5).
- Модальные окна там, где хватает раскрытия на месте.
- Мелкий серый текст ниже контраста 4,5:1 для основного содержания.

## 12. Приёмка

Готово, когда:

1. `npm run typecheck` и `npm run build` проходят, `npm run dev:mock` открывает все три экрана на синтетике.
2. Скриншоты трёх экранов при 1440×900 совпадают с постерами из `design/stageshow/stills/` по композиции, цветам, размерам текста и отступам. Отличаются только данные.
3. Путь из AGENTS.md проходится без перезагрузки:
   1. загрузить файл перетаскиванием и увидеть новую строку с этапами и итогом;
   2. открыть разбор и раскрыть «Завершение»: видны объяснение, кольцо на реплике и линия-связка;
   3. подать апелляцию, принять решение «Изменить на «Да»» и увидеть итог с исходным рядом;
   4. в оценочном листе изменить вес и сохранить версию 2;
   5. запустить «Оценить заново» с версией 2.
4. С клавиатуры доступно всё: Tab по элементам, ↑↓ по критериям, Enter и Esc, видимое кольцо фокуса.
5. При `prefers-reduced-motion` ничего не двигается, но все состояния видны.
6. В консоли браузера нет ошибок и предупреждений React.
7. Сбойный запуск, неприменимые критерии, частичный итог, звонок без отправки в модель и диалог без оценки выглядят по разделам 3.6 и 4.2.
8. Нет ни одного англицизма из словаря раздела 9 в видимом интерфейсе.

## 13. Ревизия композиции

Решение пользователя после первой реализации. Там, где этот раздел расходится с разделами выше, действует он. Стиль (шапка, панели, цвета, Inter) не меняется, меняется компоновка.

**Шрифты.** Заголовок всегда крупнее того, что он озаглавливает. Токены в `@theme`: заголовок экрана 26, заголовок панели 16/600, заголовок секции 14/600, строка и текст 14, подписи 13, мелкое 12. Номера реплик 12, цвет заголовков панелей и секций `--color-ink`.

**«Диалоги» стали дэшбордом.**

- Одна панель сверху без заголовка экрана (он только для экранного чтения): показатели «Оценено», «Средний итог», «Грубые нарушения», «Апелляции», «Внимание» и кнопки. Показатели кликабельны и фильтруют список.
- Слева вкладки и таблица с колонкой «Действие»: «Рассмотреть», «Повторить», «Оценить», «Открыть». Сортировка по итогу и времени, диалоги без итога всегда ниже.
- Справа панели «Нужно сделать» (апелляции, нарушения, сбои, неоценённые, спорные места) и «Где теряются баллы»: в скольких диалогах оператор получил меньше максимума и сколько потерял в таких диалогах, критерии без потерь одной строкой. Основа: экспорт, без решений по апелляциям.

**«Разбор диалога».**

- Над списком полоса «Набрано и потеряно»: сегмент на критерий шириной с его вес, клик открывает критерий.
- Секции и критерии раскрываются с шевроном, содержимое появляется по очереди. В строке критерия виден вклад в баллы.
- В объяснении четыре блока: «Вывод» с номерами источников, «Основание» со списком цитат, «Влияние на итог», «Правило листа» с выбранной ступенью. Цитата подсвечена прямо в реплике.

**«Оценочный лист» стал конфигурацией.** Слева критерии и полоса весов, названия переносятся. Справа заголовок критерия и группы «Основное», «Ответ и баллы», «Условия», «Уточнения для модели»: название и пояснение группы слева, поля справа. Вес задаётся ползунком и числом. Блок «Как считается» показывает баллы за каждый ответ. Условия «Когда «Да»» и «Задача шкалы» обязательны.

**Границы редактирования листа.** Прошлые оценки хранят свою версию, поэтому правки их не меняют.

- Новый критерий получает название и вес 5, новая секция название. Незаполненное поле подсвечено на месте, строка помечена «не заполнен», кнопка «Показать» ведёт к полю.
- Нельзя удалить последнюю секцию, последний критерий и единственный критерий с весом: без него итог не рассчитается.
- Секцию с критериями удаляют с выбором: перенести их в другую секцию или удалить вместе, если после этого лист останется рабочим.
- Названия секций и критериев не повторяются. Идентификатор удалённого критерия не используется снова.
- Флаг нарушения работает только с ответом Да / Нет.
- Пока есть несохранённые правки, нельзя сменить лист или начать новый. «Отменить изменения» возвращает сохранённую версию.

## 14. Вторая ревизия

Решение пользователя. Там, где этот раздел расходится с разделами выше, действует он.

**Интерпретация итога.** Каждый итог получает оценку: «Критично» (есть грубое нарушение), «Низкий» (меньше 60), «Средний» (от 60 до 80), «Высокий» (от 80). Константы в `src/lib/scoreBands.ts`. В разборе над полосой вклада перечислено, сколько и на чём потеряно.

**Грубое нарушение отмечается отдельно (с 8.11, решение пользователя).** Крупно показан итог по чек-листу, вместо метки уровня рядом стоит красная плашка «Грубое нарушение». В списке диалогов итог тоже по чек-листу, классификация «Критично» и пометка «Грубое нарушение» остаются. Раньше итог на экране обнулялся; это противоречило формулировке задания «грубая ошибка отмечается отдельно» и могло читаться жюри как итог 0.

**Скролла страницы нет.** От ширины 1024 страница не прокручивается, прокручиваются только панели.

**Шапка.** Высота 64, логотип 22, название 20, пункты 16 с отступом 36, активный пункт подчёркнут белой чертой снизу вместо таблетки. Метки «Синтетические данные» в шапке нет, она показана в самом диалоге.

**Кнопки.** Главная кнопка сплошная зелёная, у «Загрузить диалог» значок плюса. Канал и язык показаны текстом со значком, без таблеток. «Оценить заново», история и запись стали значками справа от названия диалога.

**Главная.**

- Сверху крупные счётчики со значками: «Оценено», «Грубые нарушения», «Апелляции», «Сбои оценки», «Спорные места». Клик фильтрует список.
- Таблица: «Диалог, время» (время под номером), «Канал», «Итог», «Оценка», «Отметка», «Действия» значками.
- Справа статистика: средний итог, распределение по оценкам с фильтром, средний балл по критериям, сверху слабые. Панели «Нужно сделать» и «Где теряются баллы» убраны.

**Линия к доказательству** растёт от реплики к критерию.
