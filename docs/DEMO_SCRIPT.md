# Сценарий защиты: 5 минут

План повторяет тайминг организаторов: 1 минута на интерфейс, 2 на оценку, 1 на апелляцию, 1 на замену критерия. Показываем только **синтетические чаты**, реальные звонки на экран не выводим.

## Подготовка (за 10 минут до выступления)

1. Запущены backend и frontend, открыт http://localhost:5173, загружен DEV. Если контрольный набор уже пришёл, загружен и он.
2. Проверьте, что `p1-ru-012`, `p1-ru-029` и `p1-ru-030` оценены и **у `p1-ru-030` нет апелляций**: на нём показываем апелляцию.
3. В «Оценочном листе» заранее создана **копия листа** («Копия этого листа»), на ней показываем замену критерия.
4. Во второй вкладке браузера открыт `docs/SCOREBOARD.md` (табло точности, скорости и цены) на случай вопросов.

## 0:00–1:00. Интерфейс и диалог

- Экран **«Диалоги»**: счётчики (оценено, грубые нарушения, апелляции, сбои), вкладка «Требуют внимания», цветные отметки итога.
- Одна фраза о системе: «Модель только выбирает ответ по каждому критерию и даёт доказательства, баллы считает код по чек-листу. Модель бесплатная, Nemotron 3.5 Super-VL на NVIDIA, около 40 секунд на чат; запасная модель Nemotron Ultra».
- Откройте **`p1-ru-029`**: красная плашка «Грубое нарушение», оператор оскорбил клиента.

## 1:00–3:00. Оценка, обоснование, переход к реплике, N/A, итог

- В `p1-ru-029` раскройте **«Грубые ошибки»**: вывод, цитата. Клик по номеру реплики прокручивает переписку и подсвечивает реплику.
- Покажите **«Трассу решения»**: уверенность, сработавшее правило с текстом, факты кода, на которые опирается решение.
- Откройте **`p1-ru-012`** (обрыв связи) и раскройте **«Завершение»**: стоит **N/A**, объяснено, какое условие выполнено. В блоке «Влияние на итог» видно, что вес 5 перераспределён: «Вес 5 → … после исключения неприменимых».
- Итог и полоса «Потеряно N: …» показывают, откуда взялся балл.

## 3:00–4:00. Апелляция и решение проверяющего

- Откройте **`p1-ru-030`**. Модель засчитала «Завершение» как «Да», хотя оператор только поблагодарил и попрощался.
- Кнопка **«Проверка человеком»** под баллом → «Завершение» → комментарий: «Итога и предложения помощи нет, только прощание» → «Отправить апелляцию».
- Счётчик у балла показывает «требуют внимания: 1».
- **«Принять решение» → «Изменить на «Нет»»**, причина, имя проверяющего → итог пересчитан, под ним «исходная …».
- Шапка → **«Апелляции»**: очередь проверяющего, решённая апелляция с причиной.

## 4:00–5:00. Замена критерия и применение чек-листа

- **«Оценочный лист»** → копия листа → поменяйте формулировку критерия (например, «Эмпатия» → «Оператор назвал конкретный путь в меню») или сделайте шкалу 0/3/5 → **«Сохранить версию N»**. Появится плашка «Смысл изменён: диалоги будут оценены заново».
- Переоцените один диалог по этому листу. Чтобы не ждать около 40 секунд, запустите переоценку **в начале выступления** и покажите готовый результат здесь: модель оценивает **новый смысл**, ступени шкалы новые.
- Фраза в конце: «Рубрика, JSON-схема, проверка и расчёт строятся из версии листа, код не меняется. Это проверено тестами и вживую».

## Если спросят

| Вопрос | Ответ |
|---|---|
| Точность? | Holdout (14 чатов, не участвовали в настройке) против нашей разметки: смотри README. Два человека-разметчика между собой согласны на 85–92% |
| Цена? | $0 на бесплатном API; по публичной цене около $0.005 за чат и $0.007 за звонок |
| Звонки? | В контроле их нет. Оцениваются по голосовой версии листа; по умолчанию не уходят в облако из-за персональных данных; удержание с консультацией коллеги выделяется кодом. Тексты звонков не попадают в Git |
| Защита от выдуманных доказательств? | Каждая цитата сверяется с репликой; неподтверждённая отбрасывается и помечается для проверяющего |
| Это не захардкожено? | Никаких ответов по ID диалога; контрольные диалоги оцениваются в момент импорта, журнал запуска показывает вызовы модели |
| Dynamics 365? | Статический интерфейс, относительные пути, настраиваемый адрес API и `hostAdapter` |
