# Как пользоваться Sapa: ручная проверка по шагам

Инструкция для ручного прогона всего сценария: от запуска до апелляции и замены критерия. Каждый шаг заканчивается строкой **Проверить**: что должно получиться.

## 0. Запуск

Нужны Python 3.12+, `uv`, Node 24. Файл `.env` лежит в корне `fortochka/`, заполнен из `env.txt`.

Терминал 1, backend:

```bash
cd fortochka/backend
uv run uvicorn cqa_backend.main:app --port 8000
```

Терминал 2, frontend:

```bash
cd fortochka/frontend
npm run dev
```

Откройте http://localhost:5173.

**Проверить:** открылся экран «Диалоги» с тёмно-зелёной шапкой Freedom / Sapa. Сообщения «Сервер вернул ошибку 502» нет. Если оно есть, backend не запущен.

## 1. Загрузить диалоги

1. На экране «Диалоги» справа вверху нажмите **«⋯» (Ещё)** → **«Импорт по group_id»**.
2. Введите `DEV` и нажмите **«Импортировать»** (или Enter).

**Проверить:** появилась строка «Импортировано 65, пропущено 0», в таблице 65 диалогов (`p1-ru-*`, `p1-kz-*`, `p1-en-*`, `p4-ru-*`).

Для контрольного прогона в 11:00 вместо `DEV` вводится `group_id` от организаторов.

Свой файл можно загрузить кнопкой **«Загрузить диалог»** или перетащить `.json` прямо на таблицу.

## 2. Запустить оценку

- Один диалог: в строке диалога, колонка «Действия», значок **▶ «Оценить»**.
- Все сразу: **«Оценить неоценённые»** под строкой импорта.

**Проверить:**
- в колонке «Отметка» крутится индикатор;
- оценка одного чата занимает 1–2 минуты (бесплатный NVIDIA, модель Nemotron Ultra);
- потом появляется итог, например «92.31», и цветная отметка: Критично / Низкий / Средний / Высокий.

Звонки (`p4-ru-*`) в облачную модель не отправляются, у них будет статус «не отправлен в модель». Это не сбой: так настроено из-за персональных данных (`CQA_ALLOW_VOICE_TO_CLOUD=0`).

## 3. Открыть разбор диалога

Нажмите на номер диалога, например `p1-ru-029`, или на **→ «Открыть разбор»**.

Слева «Переписка», справа «Оценка по критериям».

**Проверить:**
- вверху этапы «Разбор диалога → Оценка моделью → Проверка цитат → Расчёт итога» с временем каждого;
- полоса итога и строка «Потеряно N: …» показывает, какие критерии сняли баллы;
- у диалога с грубым нарушением есть красная плашка «Грубое нарушение».

## 4. Посмотреть объяснение по критерию

Нажмите на строку критерия, например «Управление диалогом, скорость и грамотность».

**Проверить в раскрывшемся блоке:**
- **Вывод**: короткое обоснование с номерами реплик. Клик по номеру прокручивает переписку к этой реплике и подсвечивает её.
- **Основание**: цитаты из реплик. Они дословные, код проверяет каждую.
- **Трасса решения**:
  - «Уверенность NN%»: зелёная от 85%, жёлтая от 67%, красная ниже 67%; при красной — «нужен взгляд проверяющего»;
  - «Решило правило»: «Условие «Да»», «Условие N/A», «Ступень шкалы 7» или «Уточнение команды № 2»;
  - «Почему не выше»: только у шкал, например «один заметный сбой…»;
  - «Рассуждение модели»: раскрывается по клику.
- **Влияние на итог**: вес, эффективный вес после N/A, сколько баллов дал критерий.
- **Правило**: официальный текст критерия из чек-листа.

Чтобы увидеть пример N/A, откройте `p1-ru-012` (обрыв связи). У критерия «Завершение» будет N/A с объяснением, какое условие выполнено, а его вес перераспределён между остальными.

## 5. Подать апелляцию

1. В раскрытом критерии нажмите **«Оспорить оценку»**.
2. В поле «Почему оценка неверна» напишите комментарий, например «Оператор предложил помощь в последней реплике».
3. Нажмите **«Отправить апелляцию»**.

**Проверить:** у критерия появился блок апелляции, на экране «Диалоги» вырос счётчик «Апелляции».

## 6. Решение проверяющего

1. В том же критерии, в блоке апелляции, нажмите **«Изменить оценку»**.
2. Выберите новое значение или **«Подтвердить «…»»**, чтобы оставить исходное.
3. Заполните «Причина решения» и сохраните.

**Проверить:**
- итог пересчитан сразу, без вызова модели;
- видны исходная оценка, решение и финальный результат;
- кнопка **«История оценок»** (часы рядом с заголовком диалога) показывает все прогоны.

## 7. Заменить критерий (это проверят организаторы)

1. Шапка → **«Оценочный лист»**.
2. Слева выберите критерий, например «Эмпатия и клиентоориентированность».
3. Справа поменяйте «Название критерия», текст **«Когда «Да»»**, тип ответа (Да/Нет или шкала со ступенями), вес, галочку **«Допускается «не применимо»»**.
   - Новый критерий: **«+ Критерий»**. Новая секция: **«+ Секция»**.
4. Следите за подсказкой «Сумма весов 100» и нажмите **«Сохранить версию N»**.

**Проверить:**
- появилась плашка «Смысл изменён: диалоги будут оценены заново», а старые уточнения команды для этого критерия отключились;
- вернитесь в «Диалоги», переоцените 1–2 диалога (меню повтора у диалога или «Оценить неоценённые»);
- в разборе стоит новый критерий, а модель обосновывает именно новый смысл;
- если поменяли только вес, итог пересчитывается без нового вызова модели.

## 8. Экспорт результатов

**«⋯» (Ещё)** → **«Экспорт CSV»** или **«Экспорт JSON»**.

**Проверить:** в файле на каждый диалог есть `total`, `gross_error`, по каждому критерию `status`, `answer`, `points`, `confidence` и `rule`. Экспорт содержит исходную AI-оценку, без учёта апелляций.

## 9. Отчёт

**«⋯» (Ещё)** → **«Подробный отчёт»**.

**Проверить:** средний балл по критериям, разбивка «По языкам» и «По каналам», число сбоев.

## 10. Контрольный прогон одной командой (W10)

```bash
cd fortochka/backend
uv run python -m cqa_backend.control --group-id <значение от организаторов>
```

Команда сама импортирует ровно 10 записей и проверит схему. Затем она оценит их, повторит только сбои и проверит полноту. JSON и CSV она запишет в `data/control/<группа>-<время>/`, а в консоли напечатает отчёт. Код выхода 0 означает, что все 10 диалогов получили полный результат.

## Что делать, если…

| Симптом | Причина и что делать |
|---|---|
| «Сервер вернул ошибку 502» | Не запущен backend (терминал 1) |
| Оценка висит больше 5 минут | NVIDIA перегружен. Через 240 с вызов повторится, затем включится запасная Gemma. Если диалог всё равно упал, в строке будет «Сбой», а кнопка **«Повторить»** запустит его заново |
| «Звонок не отправлен в модель» | Так задумано, см. шаг 2 |
| «Оценщик не настроен: не задан NVIDIA_API_KEY» | Нет `.env` в корне `fortochka/` |
